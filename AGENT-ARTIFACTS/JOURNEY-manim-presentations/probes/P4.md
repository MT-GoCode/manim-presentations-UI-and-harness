Barcode = a 24-cell strip in every frame, `frame | clip<<16`, read back from the presented frame through a canvas inside the rVFC callback. So every verdict above checks the pixels on screen as well as `metadata.mediaTime`.

### Two player-design findings (Chrome; WebKit to be confirmed in CI)

1. **Next must show frame 0 paused, swap on its rVFC, then `play()`.** If Next calls `play()` straight away, the incoming video's first rVFC reports frame 1 (mediaTime 0.033333). So "the next clip's pts 0 is presented before the previous video hides" (§3.11) fails. With show-paused-then-play, the first rVFC is frame 0 (barcode `1<<16`, mediaTime 0), presented 15.3 ms after the key while the old video is still in front.
2. **Before → Next on beat 0:** beat 0 is already in front on frame 0, and seeking it to 0 again presents nothing, so no rVFC fires (this hung the first player version). The player just calls `play()` there. The first new frame is then frame 1, which is correct because frame 0 is already on screen.

The CI script's player (`PLAYER_JS` in `p4/p4_webkit_ci.py`) implements both, plus the half-frame seek.

- Height dominates quality, and crf barely matters at a given height. Manim frames are flat colour, thin lines and text, which x264 codes cheaply.

## Browser: the 10-minute talk as one HTML file (Chrome)

Page: the plan's player. Clips are base64 `<script type="application/octet-stream">` blocks. A `Blob` + `URL.createObjectURL` is made only for beats within ±1 of the current beat and revoked on leave. There is one `<video>` per beat, and the previous one stays in front until the incoming one's first rVFC. Each run: open the file (`file://`, network routed to abort), wait for `Before`'s first presented frame, press Next through all 57 beats, then Previous ×3. Every Next must present the incoming beat's frame 0 and every Previous that beat's last frame, both checked by barcode. Result: **0 wrong frames and 0 media errors in all 27 runs.** Runs held `/tmp/mpres-heavy.lock`. Memory = psutil RSS sampled every 50 ms. "Renderer" = the largest `--type=renderer` process, i.e. the tab. "Tree" also counts the Chrome browser, GPU and utility processes, the Playwright node driver and the Python harness, which holds the HTML too; RSS double-counts shared pages. A blank page's renderer is 186 MB.

## WebKit / CI script

`p4/p4_webkit_ci.py` is one self-contained file. Its PEP 723 header pins `av==19.0.2`, `numpy==2.5.4`, `playwright==1.64.1` and `psutil==7.2.2`, with Python 3.12. It needs no ffmpeg binary: it makes its own barcoded clips with PyAV. It prints one JSON line per check, then a summary. It exits 0 iff play-to-`ended` and the half-frame paused seeks pass (the P5 gate). Checks:
- `baseline_blank_page`;
- `play_to_ended` (480×270);
- `paused_seek` (exact and half-frame, at the last frame, frame 0 and the middle frame);
- `transitions` (Before pts 0, Next×2, Previous to the last frame, Previous to Before, previous-in-front);
- `loop_seam` (4 wraps);
- `loop_double_buffer` (only if the seam stalls, or with `--force-fallback`);
- `click_through_r1` (130 beats) and `click_through_r1000` (the all-`src` control);
- `first_frame_h{1080,720,540}` (3 clips × 3 s, 3 runs, with process-tree RSS).

Stall rule, fixed in `seam()` before any run: a wrap whose wall gap exceeds max(3 × the median non-wrap gap, 100 ms). Local Chrome result of the same script (`p4/results/ci_chrome.jsonl`): every check passes, `p5_gate: PASS`, wall 41.6 s, whole script tree peak 1840 MB (renderer 677 MB), 0.83 cores.

## Reproduce

```bash
cd conversation-contexts/manim-presentations-harness/JOURNEY-manim-presentations/probes/p4
uv sync                                   # Python 3.12 (.python-version), av, numpy, playwright, psutil, pillow
uv run python -u gen_sources.py 8         # 57 clips, 18000 frames at 3456x2168 from the real Mixing Deluxe renders -> src/ (3m50s)
uv run python -u encode.py sweep 8 3      # 9 variants x 3 reps -> out/, results/encode.json (~15 min at load ~35)
uv run python -u quality.py               # VMAF/PSNR -> results/quality.json, crops/ (~3 min)
flock /tmp/mpres-heavy.lock uv run python -u p4_talk.py chrome 3          # -> results/talk_chrome.json (~50 s; builds html/)
flock /tmp/mpres-heavy.lock uv run python -u p4_webkit_ci.py --engine chrome --force-fallback > results/ci_chrome.jsonl
uv run python -u decode.py sweep 5        # -> results/decode.json (~30 s)
# WebKit, on GitHub macos-latest (parent):
uvx playwright@1.64.1 install webkit && uv run --script p4_webkit_ci.py --engine webkit
```

`gen_sources.py` reads the 10 chapter renders under `mixing-deluxe-presentation/manim-presenters/presentations/mixing-deluxe/build/*/media/videos/2168p30/`. The 3 loop clips (5, 22, 41; 60, 90 and 120 frames) are palindromes of real content, so their last frame steps cleanly to frame 0. Some clips hold a chapter's last frame when the chapter is shorter than the clip, which mirrors held beats. `html/` (1.3 GB) was deleted after the run and is rebuilt by `p4_talk.py`.
