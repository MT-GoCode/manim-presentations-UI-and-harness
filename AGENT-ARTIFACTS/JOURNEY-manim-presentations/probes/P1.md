# P1: Audience playback on mac-work-2 (2026-10-30)

Host: mac-work-2, M4 Max 16 cores, macOS 26.7. PySide6 6.12.0 (Essentials + Addons), Qt's FFmpeg 9.0.1, Python 3.12.15, PyAV 19.0.2.
Every run is headless: `QT_QPA_PLATFORM=offscreen`, with `QT_SCALE_FACTOR=2` so the device pixel ratio is 2, as on stage. Nothing was screen-captured.
Scripts and raw JSON: `probes/p1/` (`results/*.json`; `fonts/`).

## Decision (per §3.7 "Decided in advance (P1 + P5)")

- **Backend: `ffmpeg`.** `darwin` fails (d). It cannot load media under `offscreen`, so it can never pass P1 or P5 (see (d)). `ffmpeg` passes (a)–(f) on both stacks at both resolutions. `ffmpeg` is also what Qt 6.12 loads on macOS when `QT_MEDIA_BACKEND` is unset.
- **Widget stack: `QVideoWidget`**, provided P5 also passes on `macos-latest`. It passes P1 (a), (b), (c) and (f) at both resolutions. Sink-paint also passes all of them, so it is a valid fallback under the plan's rule if `QVideoWidget` fails P5.
- **Loops: single player with `setLoops(Infinite)`.** The seam is smooth, so the pre-decided double-buffer for loops does **not** trigger.
- **Clip switch:** no empty or black frame in any of 30 switches. The single-buffered switch is clean under the plan's black-frame criterion. **One open point for the parent / Minh:** at 3456×2168 a single-buffered switch holds A's last frame for about 120 ms (≈3.6 frames). B then starts with a burst: frames 0–3 arrive within ~20 ms. A pre-loaded paused player (Cover, then `play()`) steps to frame 1 one frame interval later (36 ms) and paces evenly at 33 ms. See (b).
- **Hold:** paused `setPosition` works, so the (f) fallback (k) is not needed. It requires two exact conditions: wait for `LoadedMedia`, and seek to `ceil(last_pts_ms)`. See (f).
- **Runtime backend check is necessary.** An unknown `QT_MEDIA_BACKEND` value silently loads ffmpeg, with no warning.
- **`g=6` confirmed.** The worst-case paused seek at 3456×2168 lands in ≈50 ms from `setPosition` (1.5 frames) at load < 40.

## Test clips

`make_clips.py` encodes exactly like `clip.ENCODE`: libx264, yuv420p, 30 fps, `threads=1`, `g=6`, crf 18, preset veryfast. It produced 3456×2168, 1920×1080 and 480×270 clips.
- Each frame carries a 12-bit code in a 4×3 grid of black/white cells (bits 0–7 = frame index, bits 8–11 = clip id) on a mid-gray background.
- Each frame is identified from the presented sink frame's pixels (luma plane, read via `QVideoFrame.map`). Each frame is also checked against `startTime()`.
- An empty frame is `!isValid()`. A black frame is a valid frame whose two gray-margin sample points are both not mid-gray.
- Clips: A (id 1, 90 frames), B (id 2, 90), L loop (id 3, 90; frame 89 steps to frame 0), S seek clip (id 4, 180 frames ≈ 6 s).
- Verified with PyAV: keyframes every 6 frames, and the last frame's code decodes as expected.

"Presented" means the frame the stack's `QVideoSink` delivers through `videoFrameChanged`, in the GUI thread. For `QVideoWidget` that is `widget.videoSink()`. For sink-paint it is the widget's own `QVideoSink`, painted with `QVideoFrame.paint` (KeepAspectRatio).

## (a) Holding the last frame after EndOfMedia

| backend | stack | res | raw (no action) | rev 14 method: re-set sink frame on EndOfMedia |
|---|---|---|---|---|
| ffmpeg | widget | 3456×2168 | sink empty 500 ms later, 5/5 | **holds frame 89, 5/5** |
| ffmpeg | widget | 1920×1080 | sink empty, 5/5 | **holds frame 89, 5/5** |
| ffmpeg | sinkpaint | 3456×2168 | sink empty, 5/5 | **holds frame 89, 5/5** |
| ffmpeg | sinkpaint | 1920×1080 | sink empty, 5/5 | **holds frame 89, 5/5** |
| darwin | both | both | never reaches EndOfMedia; 0 frames | n/a |

- All 90 frames are presented in every run, with none missing (`missing_indices` = []).
- **Event order at the end** (`eom_order.py`, 3 runs per stack × resolution, all identical): `frame 89` → about 33 ms later an **empty frame** → `StoppedState` → `EndOfMedia` → the handler calls `sink.setVideoFrame(last valid frame)` → `frame 89`.
  - The empty frame exists for **0.05–0.08 ms** before the reset, inside one event-loop pass, so no repaint can run in between.
  - Implementation note: re-set from the `EndOfMedia` handler, using the last *valid* frame kept from `videoFrameChanged`. The empty frame arrives before the status change, so do not re-read the sink at that point.
  - Sink-paint can additionally skip invalid frames in `paintEvent`.

## (d) Does `offscreen` work?

| backend | stack | loads plugin | reaches EndOfMedia | frames presented |
|---|---|---|---|---|
| ffmpeg | widget | `libffmpegmediaplugin.dylib` | yes | all |
| ffmpeg | sinkpaint | `libffmpegmediaplugin.dylib` | yes | all |
| darwin | widget | `libdarwinmediaplugin.dylib` | **no**: stuck in `LoadingMedia` | **0** |
| darwin | sinkpaint | `libdarwinmediaplugin.dylib` | **no** | **0** |

- **Cause for darwin:** the offscreen QPA uses `QUnixEventDispatcherQPA`, not a CoreFoundation dispatcher. AVFoundation's main-queue completion handlers never run, so loading never completes. `QT_EVENT_DISPATCHER_CORE_FOUNDATION=1` does not change the dispatcher.
- Diagnostic only, not shippable: pumping `CFRunLoopRunInMode` from a 1 ms `QTimer` lets darwin reach `EndOfMedia`. Even then it presents **0 frames** to either stack's sink.
- Under offscreen, ffmpeg logs `No RHI backend. Using CPU conversion.` Frames arrive as `Format_NV12`.
- **Sink-paint paint cost** (window 1728×1084 logical at DPR 2): median 9.1 ms, max 95.7 ms over 9164 paints in the full matrix. In the load ≤ 40 re-time: median 12.3 ms, max 48.7 ms over 1796 paints. This is CPU conversion under offscreen, not the stage render path.

**Plugin identity** (dyld image scan via `_dyld_image_count` / `_dyld_get_image_name` after constructing `QMediaPlayer`):

| `QT_MEDIA_BACKEND` | loaded | Qt warning |
|---|---|---|
| `ffmpeg` | `libffmpegmediaplugin.dylib` | none |
| `darwin` | `libdarwinmediaplugin.dylib` | none |
| unset | `libffmpegmediaplugin.dylib` | none |
| `bogus` | `libffmpegmediaplugin.dylib` | **none, a silent substitution** (plays normally) |
| `windows` (a real backend name, absent on macOS) | `libffmpegmediaplugin.dylib` | **none** |

Only one media plugin is ever loaded, and the scan at the end of a run shows the same single image. So the plan's runtime identity check is the only way to detect a mismatch.

**Hold** (fresh player, paused `setPosition`), 5 runs per variant per cell, identical across both stacks and both resolutions:

| order | position (ms) | presented | verdict |
|---|---|---|---|
| `setSource`; `pause()`; `setPosition` immediately | 2966, 2967, 2999 | frame 0, `startTime` 0 (the seek is discarded) | **fail** |
| wait for `LoadedMedia`/`BufferedMedia`, then `setPosition` | 2966 = floor(last_pts) | frame 88, `startTime` 2933333 | fail (the position lies inside frame 88) |
| same | **2967 = ceil(last_pts_ms)** | **frame 89, `startTime` 2966667 = last_pts exactly** | **pass 5/5** |
| same | 2999 = duration − 1 | frame 89, `startTime` 2966667 | pass 5/5 |

- In every passing run, no other frame is presented before frame 89. Frame 0 does not flash first.
- Time to the Hold frame, from `setSource` (median / max, ms): widget 3456 72.3 / 96.0 and 1920 21.0 / 22.6; sinkpaint 3456 64.6 / 68.4 and 1920 33.5 / 58.4.
- **Verdict (f): pass.**
  - Exact recipe: Hold = `setSource(c)`; `pause()`; on `mediaStatus ∈ {LoadedMedia, BufferedMedia}` call `setPosition(ceil(last_pts_us / 1000))`.
  - Check the result through the sink frame's `startTime() == last_pts_us`.
- The fallback is therefore not needed. It was measured anyway: playing muted from `last_pts − k·frame` reaches `EndOfMedia` holding frame 89 for **every k in 0..12, 5/5** in each cell. The smallest reliable k is 0.

## Unlink while looping (§3.5 parallel correctness)

The loop clip was copied to a temp path and played with `setLoops(Infinite)`. After 1.5 s the file was unlinked, and playback continued for 9 s.
- `lsof` shows the file open before the unlink, in every cell (ffmpeg × both stacks × both resolutions).
- After the unlink: 269–274 frames were presented (all of the 9 s), with continued wraps. The analysis counts 2–3 wraps after trimming to the first frame 0. There were no `errorOccurred` signals and no empty frames.
- **Verdict:** the ffmpeg backend keeps its file descriptor and does not reopen the file on each wrap.

## CI (P5)

The commands run from a checkout containing only `p1/` (`make_clips.py`, `p5_qt.py`, `summarize.py`, `pyproject.toml`, `uv.lock`, `.python-version`).
- They were dry-run locally from exactly that layout (`/tmp/p5ci`).
- `p5_qt.py` refuses to run unless `QT_QPA_PLATFORM=offscreen`.
- It needs only the stdlib, PySide6, numpy, and `lsof` (present on macOS).

```bash
export QT_QPA_PLATFORM=offscreen
uv run --project p1 python -u p1/make_clips.py clips --res 480x270 1920x1080 --clips A B L S
mkdir -p p5-results
for s in widget sinkpaint; do
  uv run --project p1 python -u p1/p5_qt.py --backend ffmpeg --stack $s --clips clips --res 480x270 --res 1920x1080 \
    --reps 3 --checks backend,a,b,c,f,seek,unlink,start --out p5-results/ffmpeg_$s.json
  # darwin is expected to fail under offscreen (see (d)); 1 rep at 480x270 records it without the cost of its timeouts
  uv run --project p1 python -u p1/p5_qt.py --backend darwin --stack $s --clips clips --res 480x270 \
    --reps 1 --checks backend,a,f --out p5-results/darwin_$s.json
done
uv run --project p1 python p1/summarize.py p5-results
```

**P5 pass criteria, read from the JSON per backend × stack:**
- `loaded_media_plugins` equals the requested backend's dylib.
- `a.reset.holds_last_frame` is true, meaning `EndOfMedia` was reached and the last-frame pts arrived and is held.
- `c.wraps_seen` > 0 with `drops_at_wrap` = 0, meaning `setLoops(Infinite)` wraps.
- `f.cover_ok` is true, and `f.hold_ok["after_loaded@<ceil(last_pts_ms)>"]` is true.

Expected result on the runner: ffmpeg passes on both stacks, and darwin presents 0 frames.
