## LOW

### L1. Two concurrent exports to one `--out` share one partial file
- Location: `export.py:80`, `partial = out.with_name(f".{out.name}.tmp")`.
- Principle: robustness under concurrency. Concurrency must be prevented, not assumed absent. No failure may look like a success.
- Defect: both processes open the same `.x.html.tmp` with `"w"` and write into it at their own offsets. The first `os.replace` publishes interleaved bytes and exits 0. The second `os.replace` raises `FileNotFoundError` as a traceback. (The test fixture `exported` takes a lock for exactly this reason.)
- Fix: give each process its own partial file. Use `fd, name = tempfile.mkstemp(dir=out.parent, prefix=f".{out.name}.", suffix=".tmp")`, then open `fd` (`os.fdopen(fd, "w", encoding="utf-8")`). The `finally` unlink stays.

### L2. A failed encode still waits for every queued encode
- Location: `export.py:96-99`. When `pool.map` raises, leaving the `with` block calls `shutdown(wait=True)`, which runs all pending jobs.
- Principle: lower latency. Only load-bearing work may sit on the path.
- Effect: with one broken clip early in a 57-beat 1080p talk, the user waits for the other ~56 encodes before the error prints.
- Fix: catch the error, call `pool.shutdown(cancel_futures=True)`, and re-raise. Or replace the `with` block with `try/finally: pool.shutdown(cancel_futures=True)`.

### L4. A failed clip's element is never removed
- Location: `player.html:97-102`. On a current-generation `error`, `v` stays in `#stage`. The next successful show releases only `front`. So each failed clip leaves one dead `<video>` in the DOM for the rest of the session.
- Fix: call `v.remove()` before the throw. (`front` is unchanged, so the last frame still stays on screen.)

### L5. The frame rate lives in two places in the fixture
- Location: `tests/export/fixtures/frames.manim-presentation/helpers/code.py:8` (`FPS = 25  # talk.toml's frame rate`) and `talk.toml`'s `frame_rate`.
- Principle: single source of truth. If someone edits talk.toml alone, the counter steps by the wrong amount, and every frame-code assertion fails far from the cause.
- Fix: read the rate where the scene runs (`manim.config.frame_rate`). If the harness does not guarantee it, keep the constant and add an assertion that it equals the config value.

### L6. `TEST_COST["export"]` was measured with Chrome only

- Impact: none today. CI runs at width 1, and the browser fixture is module-scoped and parametrized, so only one engine is live per worker at a time. If WebKit's process tree is heavier than Chrome's 1345 MiB, local xdist slots would be undersized.
- Fix: sample one WebKit run when WebKit is available, and record the larger value.
