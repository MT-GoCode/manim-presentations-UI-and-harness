## HIGH

### H1. The no-black-frame test cannot see the outgoing video go black
- Location: `tests/export/frames.py:133` (`c == 0 or (c >> 8) - 1 == old` for the outgoing element).
- Principle: tests must be falsifiable and exact, not exhaust-based. This is a ★ NORTH-STAR item ("no black frame on any transition").
- Defect: on every transition, the outgoing element may read code 0. The docstring says this exists only for a loop's own wrap, but the assertion applies it to every beat. A code of 0 means "unreadable", and unreadable includes black.
- Mutant `blackout-outgoing-at-insert`: in `show()`, after `stage.prepend(v)`, add `front.removeAttribute("src"); front.load();`. The old video then stays in front and black until the new one is raised. Result: `test_every_transition_shows_the_right_frame_and_nothing_else_on_the_way[chrome]` **SURVIVED**. So did the four transitions in `test_buttons…` and the five in `test_blob_urls…`. Only two unrelated assertions kill it: the `<= {0, 2}` set in `test_presses_faster…`, and one transition in `test_replay_and_jumps…`.
- Fix: in `T.watch`, record the `seeking` flag of the front video with its code: `[code, isNew, v.seeking]`. In `transition`, accept code 0 for the outgoing element only when `old` is the loop beat and that video is `seeking`. In code: `c == 0 and old == LOOP and seeking or (c >> 8) - 1 == old`. Then re-run the mutant against the dedicated test and see it go red.

- Location: `player.html:88` (`(frame + 0.5) / M.fps`), against STRATA E2 ("mutants: seek to k/fps → Chrome reads k−1").

### M2. "A jump to the current beat" is tested through an event a real user cannot cause
- Location: `player.html:117` (`jump` `change`), and `test_player.py:96`.
- Principle: tests mimic the real use case. No code path that only a test can reach.
- Defect: a `<select>` fires `change` only when its selection changes (HTML spec). After Next onto b, the list already shows b, so a viewer who picks b does nothing. The Presenter's timeline click would show b's last frame. Playwright's `selectOptions` dispatches `input` and `change` every time, even when the value does not change (read from `playwright/driver/package/lib/coreBundle.js`: `select.dispatchEvent(new Event("change", …))`, with no condition). So the test passes, but the behaviour it claims does not exist for a user.
- Fix: decide in DECISIONS which control owns jump-to-the-current-beat. The cheapest choice is E3's transcript-panel click: every click fires, so jump-to-current gets its test there, and the select test at `:96` is deleted. The other choice is to replace the `<select>` with a list of buttons.

### M3. Each show decodes a neighbour's base64 on the main thread before the shown clip gets its source
- Location: `player.html:76` (`keepWindow(beat)` before `v.src = blobUrl(beat)`).
- Principle: lower latency. Only load-bearing work may sit on the critical path.
- Measured: `atob` plus the byte loop for 8 MiB takes 167 ms (node, this machine). At P4's rate (163 MiB for 10 min), 8 MiB is one 30 s beat.
- Defect: on Next from i to i+1, beats i and i+1 already have Blobs, but `keepWindow` first decodes beat i+2 synchronously. Every Next therefore waits for a clip it does not show. A jump waits for up to three decodes.
- Fix: set `v.src = blobUrl(beat)` first. Move `keepWindow(beat)` into the swap handler, beside `dropOutside(beat)`. A Next then decodes nothing on its path (the target was already a neighbour), and the window stays exactly ±1 after every swap.

### M4. A clip that fails to load is silent to the viewer, and that path never runs
- Location: `player.html:90`.
- Principle: no failure that looks like a success. No code path nobody has seen execute.
- Defect: on an error, the current show throws to the console. The position has already moved (`act` sets it before `show`), but the old frame stays on screen with no sign of failure. The next press then moves on from a beat the viewer never saw.
- Mutant `no-error-handler` (the listener deleted): every test **SURVIVED**.
- Fix: put the failure on screen, for example `document.body.classList.add("failed")` and the message in `#bar`, then throw. Add one test that copies `page_file`, truncates the base64 of `clip-1`, presses Next twice, and asserts three things: the failure text, the front video still shows beat 0's frames, and exactly one `pageerror` naming clip 1. (The fixture's "no page error" check needs this one case to be expected.)

### M5. STRATA E2's cost measurement was not done or recorded
- Location: STRATA E2 ("Measure the export test process-tree peak … if the export cost exceeds conftest's heaviest TEST_COST … report to the parent"). `tests/conftest.py:30` has no `export` entry. No DECISIONS line gives a number.
- Principle: no arbitrary limits. Every constant comes from a measurement.
- Measured here (Chrome only, one worker, `test_player.py`, summed RSS of the pytest process tree, sampled every 0.2 s): **1368 MiB and 1.48 cores**. Both exceed `build`'s (1.1 cores, 911 MiB), so the xdist slot size is too small for export tests, and STRATA requires a report to the parent. (Summed RSS counts Chrome's shared pages more than once, so the true figure is lower. It must be measured, not assumed.) With WebKit, each xdist worker holds both browsers for the whole session, so the real peak is higher.
- Fix: measure on CI with both engines, record the numbers in DECISIONS, and report to the parent if they exceed `build`'s (1.1 cores, 911 MiB). Also record the CI wall time of this run.
