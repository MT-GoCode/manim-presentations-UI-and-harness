### H1. The refusal-routing tests cannot fail: unrouted exceptions pass them
- Location: `tests/export/test_file.py:47`, `:76-79`, `:112`. The code under test is `manim_presentations/cli.py:81`.
- Principle: tests must be falsifiable (the gate), mark-then-route exactness, and no failure that looks like a success.
- Defect: an uncaught Python exception also exits with code 1, and its traceback contains the exception message. So `returncode == 1 and "<message>" in stderr` holds whether `run_export` routes the exception or the process crashes.
- Mutants that SURVIVE (each test stayed green):
  - `TooBig` removed from the `except` tuple: `test_an_encode_job_too_big…` still passes.
  - `Stale` removed: `test_a_stale_or_unbuilt_talk_is_refused` still passes.
  - `IncompatibleBuild` removed: same test still passes.
  - `ExportError` removed: `test_height_defaults_to_the_source_and_refuses_above_it` still passes.
- The STRATA E1 line "`run_export` routes IncompatibleBuild, Stale, TooBig, ExportError to exit 1" is therefore untested.
- Fix: assert the routed shape exactly, in one helper that all four tests use:
  ```python
  def refused(r, text):
      assert r.returncode == 1 and r.stderr == f"error: {…}\n"
  ```
  At minimum use `r.stderr.startswith("error: ") and "Traceback" not in r.stderr`. Then re-run the four mutants above and see them go red.

- Location: `manim_presentations/export.py:93-94`, and the boundary at `cli.py:80`.
- Principle: robustness at the boundary (validate once, at the edge), lowest latency, and no unrouted failures.
- Observed: `mpres export <talk> --out /tmp/review-e1-tools/nope/x.html` ran the full width and encode phases. Then it died with `FileNotFoundError: … '/private/tmp/review-e1-tools/nope/.x.html.tmp'`, exit 1, as a raw traceback. An `--out` that names a directory fails the same way at `os.replace`.
- Fix: validate in `cli.py`, before `export` runs. The parent of `--out` must be an existing directory, and `--out` must not be a directory. Refuse with `error: …` (an argparse `type=` like `positive` and `even`, or a `BoundaryError`-style check). Add one test that names it: `--out <missing>/x.html` exits with the routed message and creates nothing under `build/.export`.

## LOW

### L1. The partial page is not removed if writing it fails
- Location: `export.py:93-100`.
- Principle: no cruft left behind, and robustness under system faults.
- Defect: if the write fails (disk full, an interrupt, or the M1 case after you fix the parent check), `.<name>.tmp` stays next to `--out`. The `finally` removes only `tmp`.
- Fix: add `partial.unlink(missing_ok=True)` to the `finally`. Keep the partial next to `--out`, because `os.replace` needs the same filesystem, and `tmp` is not guaranteed to be on it. A mid-write failure is hard to provoke from a test, so delete the vacuous `.*.tmp` clause from `test_a_failed_encode…` and do not keep an assertion that guards nothing.

### L2. The pts-copy line is dead code: removing it gives byte-identical clips
- Location: `export.py:54` (`g.pts, g.time_base = f.pts, f.time_base`).
- Principle: minimality (the line must earn its place), and tests must cover each load-bearing line.
- Mutant: delete the line. SURVIVES (`test_every_frame…` green, fps and every frame code unchanged).

- Fix: delete the line. It is dead code.

### L5. The comment on `DOM_CODE` is inaccurate, and the key choice differs from the Presenter on non-QWERTY layouts
- Location: `export.py:27-28`.
- Principle: comments state true invariants.
- Defect: Qt's `Qt::Key_R` is the logical key (layout-dependent). It is not a physical key. `KeyboardEvent.code == "KeyR"` is the physical QWERTY-R position. On Dvorak, `KeyR` is the key that types "p". So "the physical key, as Qt's key codes are" is false, and the page's R differs from the Presenter's R there.
- The arrows and PageUp/PageDown are the same either way.
- Fix: this is a DECISIONS-level item for the parent. To mirror Qt, match `KeyboardEvent.key` (`"ArrowUp"`, `"PageUp"`, `"r"`/`"R"`). Otherwise keep `code` and correct the comment to say that the page deliberately uses physical positions.

If the fixture text drifts, the build has nothing to render, and the test fails confusingly (the waiting line never comes). Fix: `assert new != old` before writing, the same pattern `engine_copy` already uses (`text.count(old) == 1`).
- `ProcessPoolExecutor(n)` (`export.py:78`) has no explicit `mp_context`. STRATA says "spawn". It is spawn on macOS by default, so behavior is correct on every supported host today. Fix: `mp_context=multiprocessing.get_context("spawn")` makes STRATA's decision explicit. Optional.
