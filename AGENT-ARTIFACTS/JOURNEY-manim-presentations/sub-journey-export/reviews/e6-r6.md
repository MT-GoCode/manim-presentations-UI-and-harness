## MEDIUM

### M1. A `<!--<script` anywhere in the manifest's text disables the whole player, with no error
- Location: `manim_presentations/export.py:126`, which is `safe = json.dumps(manifest).replace("</", "<\\/")  # no string in it can close the script element`.
- Principles: no fallbacks, and a failure must never look like success. Data from outside is validated once, at the boundary. The comment claims a guarantee that the code does not give.
- Mechanism (HTML parsing): inside a `<script>`, the sequence `<!--` followed by `<script` puts the parser in the "script data double escaped" state. In that state, the real `</script>` that export writes after the JSON does not close the element. The manifest element then absorbs the clip blocks and the player's own `<script>`, so no player code runs. The manifest carries text from script.md: the talk title, and every beat and chapter title. With `--transcript`, it also carries narration and notes. A talk about HTML can easily contain this string.
- Reproduced in stock Chrome (`/tmp/review-e6-probe/probe.py`). The probe writes a manifest with export.py's exact escaping, then a clip block, then an inline script:
  - `Plain` → the inline script runs.
  - `Talk about <!--<script> tags` → **the inline script never runs. There is no page error.** The page is blank, and the exit code was 0.
  - `x <!-- y -->` → the inline script runs (only `<!--` followed by `<script` triggers it).
- Fix (verified with the same probe: both `<!--<script>` and `</script>` titles parse and the script runs). Escape every `<`. JSON allows `<`, and `JSON.parse` restores it:
  ```python
  safe = json.dumps(manifest).replace("<", "\\u003c")  # no "<" at all: nothing in it can open or close a tag
  ```
  This replaces the `</` rule, so the code stays one line.
- Test: make the fixture talk title `Frame codes <&> <!--<script>` in `script.md`. Then change the `<title>` assertion in `test_file.py:51` to `Frame codes &lt;&amp;&gt; &lt;!--&lt;script&gt;`. On 6b64c05, every player test then fails at `open_player`'s `settle(0, 0)`, because the player never runs. The fix turns them green. The existing `</script>` beat title stays as the closing-tag case. This edits the fixture, so the session build redoes once.

## LOW

### L1. The exported page is written with mode 0600 (owner-only), not 0644
- Location: `export.py:79` (`tempfile.mkstemp(...)`), then `os.replace(partial, out)` at line 135.
- Principle: a robust boundary. The product is "one file to send". `mkstemp` creates its file as 0600 so that only the owner can read it, and `os.replace` keeps that mode.
- Measured: a real `mpres export` wrote `-rw------- /tmp/review-e6-probe/f.html`. Before round 4, `open()` gave 0644 under umask 022.
- Impact: in a folder that a web server or another account reads (for example `~/Sites` or a shared folder), the page fails with a 403 or a permission error. A copy by mail or Drive is not affected.
- Fix: after `os.close(fd)`, set the mode that a plain `open()` would give:
  ```python
  umask = os.umask(0); os.umask(umask)
  os.chmod(name, 0o666 & ~umask)
  ```
  Test: in `test_every_frame…`, assert `stat.S_IMODE(out.stat().st_mode) & 0o044`.
