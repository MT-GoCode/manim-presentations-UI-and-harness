## MEDIUM

### M1. The jump list's sync to the position has no test. Without it, a jump back to the same beat silently does nothing.
- Location: `manim_presentations/player.html:146` (`jump.value = position.kind === "at" ? position.slug : "";`).
- Principle: every test is falsifiable. Every load-bearing line has a mutant that a test kills. Plan §3.9 requires "a jump list showing titles", and the list is one of the player's three controls.
- Mutant `jump-value-not-synced` (delete line 146): **SURVIVED** all of `test_player.py` and `test_transcript.py` (16 passed).
- Impact: without the line, the list keeps showing the last picked beat after keys, buttons or a panel click move the position. Example: the user picks `d`, then presses ↑ to `c`. The list still says `d`. Picking `d` again fires no `change` event, because a real `<select>` fires `change` only on a new value. So the jump does nothing, with no error.
- Fix (verified here: green on 6e9ecfb, red on the mutant at the value assertion). Add to `tests/export/test_player.py`:
  ```python
  def test_the_jump_list_follows_the_position_so_a_jump_back_works(player, frames):
      player.transition(lambda: player.page.select_option("#jump", "d"), 0, 3, frames[3] - 1)
      player.transition(press(player, "ArrowUp"), 3, 2, 0)
      assert player.page.eval_on_selector("#jump", "s => s.value") == "c"
      player.transition(lambda: player.page.select_option("#jump", "d"), 2, 3, frames[3] - 1)
  ```
  The value assertion is the one that kills the mutant. Playwright's `select_option` dispatches `change` even when the value is unchanged, so the last line alone cannot catch the stale value that a real user's re-pick would hit.
