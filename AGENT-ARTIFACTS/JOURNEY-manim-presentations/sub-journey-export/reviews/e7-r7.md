## MEDIUM

### M1. The e2e chain passes when the player never plays anything, and when the last clip is broken
- Location: `tests/e2e/test_cli_chain.py:90`, which is `return v.ended || v.loop;`.
- Principles:
  - Tests must be falsifiable and load-bearing.
  - Check the thing itself, not its exhaust. `v.loop` is an attribute the player sets, not evidence that the beat played.
- Mechanism: the template talk's last beat (`keeps-going`) is a loop. So the final wait is satisfied as soon as a loop-flagged video is in front, whether or not it plays. The per-beat waits check only that a new element with `readyState >= 2` was raised. No step observes playback.
- Mutants (both SURVIVED on 9bbd1f6):
  - `never-plays` (player.html:96, `if (play)` changed to `if (false)`): the player never calls `play()`, and the e2e test still passes (21 s). The frame-code suite in `tests/export` kills this mutant, but STRATA E3's e2e claim is "the page clicks through every beat to the end".
  - `e2e-last-clip-truncated` (export.py:135, the last clip cut to 2000 bytes): passes. A probe (`/tmp/review-e7-work/e2e_probe.py`) shows what happens in Chrome. The truncated loop loads its first frame, is raised, and then stalls at `readyState` 1. It shows no `error` and no status, so the viewer gets a frozen last beat while the test is green.
- Fix (verified in /tmp: the clean run passes in 19 s, and both mutants are killed). Replace line 90 with:
  ```python
          page.evaluate(  # the last beat ends, or (a loop) wraps: a seek the browser makes, so it played to its end
              f"() => {{ const v = ({front})(); for (const e of ['ended', 'seeked']) v.addEventListener(e, () => (window.done = true)); }}"
          )
          page.wait_for_function(f"() => window.done || ({front})().ended")
  ```
  The listeners are added after the swap, so the show's own `seeked` (the one that raised the element) has already fired and cannot satisfy the wait. Only a loop wrap or `ended` can.

## LOW

### L1. `--height` help hard-codes 1080, a second copy of `export.H0`
- Location: `manim_presentations/cli.py:111`, `help="video height (default: min(1080, the source height))"`.
- Principle: single source of truth. If P4's `H0` changes, the help text is silently wrong. `--crf` already avoids this problem: its help says "default: measured, printed".
- Fix: `help="video height, even (default: the measured web height or the source height, whichever is lower; printed)"`. This keeps cli free of the `av` import that `export` would bring.

### L2. `--transcript none` help says "no text of the script", but the default page carries every title from script.md
- Location: `manim_presentations/cli.py:119`. The same claim is at `tests/export/test_file.py:54` (`# the default: no script text anywhere`).
- Principle: an interface must state its real contract. A user who trusts the help text for privacy can be misled. The talk title, the chapter titles and the beat titles are in every export, by design (plan §3.2: "the title is what people see ... the export's jump list"). The test checks only NARRATION and NOTES, which is correct.
- Fix: help `none: titles only, no narration or notes`. Change the test comment to `# the default: no narration or notes anywhere`.
